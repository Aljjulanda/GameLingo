## iOS changes

- Control Center now uses a static configuration with a constant primary Label
  and system controller symbol. No value provider, optional value, filesystem
  lookup, or App Group is involved in rendering. The existing in-app toggle
  action remains responsible for reading actual session state. This removes
  another possible rendering dependency; it cannot repair a missing/invalidly
  signed extension or prove iOS registered a private-store package correctly.
- Install a retained UNUserNotificationCenterDelegate during app launch.
  Explicitly request banner/list presentation for session notifications when
  the app is inactive (such as a Control Center transition). Active app status
  continues using the glass banner. A manual test notification requests system
  presentation even while the app is active. This covers a potential foreground
  presentation gap; no actual device delegate invocation has been observed.
- Translation/language settings now provide separate glass-banner and system
  notification tests. They do not start a translation/PS5 session. The system
  test uses existing permission, asks only if undetermined in the active app,
  and displays denial/scheduling errors instead of silently claiming delivery.
  Scheduling success does not establish that the OS displayed a banner.
- Show the installed app and embedded WidgetKit extension build numbers. Warn
  when the extension is missing or mismatched; explicitly distinguish file
  presence from signing validity/OS registration. Show alert permission/style
  and scheduling diagnostics. Focus and user banner preferences remain in control.
- iOS app and extension build numbers increase to 14. No new Android source or
  version change is required; actual TV Build 14 installation above is complete.
