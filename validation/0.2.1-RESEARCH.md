# 0.2.1 source research

Actual repository source was cloned/read before implementation. No source code from these projects was copied into GameLingo; the changes use independently implemented, bounded real-time policies.

| Project / reviewed revision | Relevant actual code | Finding and decision |
|---|---|---|
| [SubtitleEdit](https://github.com/SubtitleEdit/subtitleedit/tree/439b85eb17059b31339d92fca2fde33e781a6b86), MIT | `src/ui/Features/Video/VideoOcr/VideoOcrLineBuilder.cs`, `VideoOcrTimingRefiner.cs` | Consecutive temporal groups, bounded gap bridging, duration/confidence-weighted wording votes and Levenshtein similarity. Adopt short-gap continuity and bounded observation evidence, while keeping first publication responsive and meaningful game instructions protected. Do not import batch timing refinement or a video-processing dependency. |
| [VideOCR](https://github.com/timminator/VideOCR/tree/548f8753d169539e56a0fb4ba532a53d8b7a8c82), MIT | `CLI/videocr/models.py` (`PredictedSubtitle`, final wording counts/confidence); `video.py` (`_process_single_zone`); `utils.py` | Confidence-selected readings, count/tie-break consensus, similarity plus gap merging and later cleanup. Adopt bounded evidence for cosmetic OCR variants; reject a global 80% threshold for short/semantic game instructions and avoid delayed batch rewriting. |
| [subtitle-extract](https://github.com/ramcana/subtitle-extract/tree/bb6d6e47965dc1c9e7177faa1b6a8f0fdf6bb892), MIT | `extractor.py` (`caption_key`, `group_samples`), `tests/test_cleanup.py` | Conservative punctuation/wrapping normalization and longest-observed variants; blank runs remain repetition boundaries. Preserve a real-disappearance boundary; bridge only a measured short OCR dropout rather than merging identical text forever. |

Android [BidiFormatter](https://developer.android.com/reference/android/text/BidiFormatter) uses embedding controls and directional reset marks. Android [Layout](https://developer.android.com/reference/android/text/Layout) and [StaticLayout](https://developer.android.com/reference/android/text/StaticLayout) expose actual run/glyph positioning, which is needed to validate the colon; string equality cannot do so. Directional isolates are preferred for independently embedded names/terms, with the colon outside the English name's isolate in an explicitly RTL paragraph. Meaningful brackets/quotes remain intact. The alternative BidiFormatter output is compared in device tests; no AndroidX dependency is needed.

Apple [Vision text recognition](https://developer.apple.com/documentation/vision/recognizing-text-in-images) supplies individual recognized observations and boxes. Structured text/geometry/confidence should survive selection instead of being irreversibly flattened before speaker classification. The existing OCR request count, ROI, sampling cadence and background CPU setting are retained. Coordinate assumptions are verified with generated-image integration assertions before changing them.
