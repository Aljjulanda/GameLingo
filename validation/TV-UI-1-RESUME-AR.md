# تحديث واجهة التلفزيون — نقطة استئناف

**الحالة الأحدث: نجح البناء المحلي وكل الاختبارات الـ54، وراجعت ثماني صور UI وتحققت من APK والمفتاح الأصلي.** [النتيجة وبصمات التسليم](TV-UI-1-RESULTS-AR.md). APK جاهز محليًا؛ التثبيت على الجهاز لم يحدث لعدم استجابته. لا حاجة لبناء آخر أو إعادة بحث الواجهة عند الاستئناف؛ أكمل خطوة الوصول/التثبيت بعد رد المستخدم، مع التحقق من هوية TCL قبل أي كتابة. السجل أدناه يحفظ المحاولات التاريخية، ولا يمثل فشلًا قائمًا.

طلب المستخدم بعد عمل الآيفون: «من تخلص حدث برنامج التلفزيون»، ثم سأل إن كان قد حدث وأذن بالمتابعة. دفعة الآيفون عند `42be152f09cad49667d69e384c9faf11d3869569` مقبولة بالمحاكي؛ [نتائجها](CURRENT-MENU-1-RESULTS-AR.md). لا بناء GitHub جديد في دفعة TV الحالية؛ استُخدمت سلسلة Android المحلية الموجودة. تبقى قاعدة التوقف عند إرسال أي GitHub build نافذة.

## النطاق والتوافق

الأساس Android TV 0.7.0-preview.1 (11)، والحزمة `dev.gamelingo.tv`. الدفعة الجديدة 0.8.0-preview.1 (12)، بنفس الحزمة ومفتاح التوقيع الأصلي SHA-256 `48cf8a45a37f4e5c338f98fa7d5135c7cdbaf59d50b39b8bf591a79622a28e38`؛ فُحص المفتاح الموجود خارج Git قبل البناء. لا مفاتيح أو بيانات اقتران في ملفات التسليم.

أُعيد تنظيم MainActivity إلى الرئيسية / الاتصال / المظهر / المساعدة. الرئيسية حالة وإجراء واضحان بحسب الإذن والاقتران والاستقبال والمحاولة والمعاينة؛ بيانات الحالة القديمة وحدها لا تثبت اتصالًا. المتصل يبدأ الترجمة من المصدر ويختار HDMI بالريموت. يبقى الاتصال بالمصدر المحفوظ تلقائيًا عند فتح التطبيق كما في الأساس، مع زر إيقاف واضح. QR والإدخال اليدوي وإعادة الاتصال دون رمز جديد في قسم واحد. المظهر يعزل المعاينة المستمرة عن الاستقبال، ويبقي الموضع ومحرر ROI؛ التشخيص وسجل ADB الاختياري في المساعدة.

أزرار كبيرة بمؤشر تركيز أبيض/بترولي ومسارات أسهم RTL صريحة؛ Back من الأقسام يعود للرئيسية. تبقى النماذج قابلة للتمرير والخط عبر sp، ويُختبر الحجم العادي و1.5×. الإذن يظهر عند الحاجة فقط. لا تغيير للإطار أو مكتبات التطبيق أو renderer أو مؤقتات الحوار والقوائم أو TLS أو المصادقة أو البروتوكول. أضيفت getters لحالة Receiver لتغذية الواجهة فقط، دون تغيير رسائل الشبكة. تبقى خيارات المستخدم المستقلة وبيانات SharedPreferences وAndroidKeyStore كما هي.

## البناء والأدلة الحالية

الأدوات الموجودة: JDK21 / Gradle8.9 / AGP8.5.2 / Kotlin1.9.24 / SDK34، مع minSdk26 وtargetSdk32 كما كانا. لا تبعيات تطبيق جديدة. استُخدم debug signing الأصلي، لا مفتاح عشوائي جديد. الفحوص المقصودة: جميع اختبارات Android السابقة، وست حالات لحالة الرئيسية وثلاث حالات تنقل/إذن/حفظ ورسم UI، وassembleDebug وassembleDebugAndroidTest.

توقفت محاولة محلية مبكرة في offline mode لعدم وجود ZXing3.5.3 في cache قديم؛ استُخدم cache الأدوات الحالي والتبعية المثبتة نفسها. تجمّع التطبيق بعدها، لكن تجميع الاختبار الجديد أخفق لاستخدام type argument غير مطلوب في `RuntimeEnvironment.getApplication`؛ فُحص السجل وصُحح الاستدعاء دون تغيير أي assertion. حُفظ السجل في `android-tv/app/build/tv-ui-build-compile-failure.log`. التشغيل التالي مسجل في `android-tv/app/build/tv-ui-build.log`؛ **لم تُقبل فحوصه أو APK بعد في هذه النقطة**. لا تكرر البناء بلا قراءة هذا السجل والنتائج.

أكمل التشغيل التالي 54 حالة وفشل في حالتين جديدتين فقط: غياب التركيز الأولي، ومقارنة نقطتي خلفية متماثلتين في guard الصورة. فُحص XML الاختبار وسجل `tv-ui-build-runtime-failure.log` وحُفظا. جُعلت الأزرار قابلة للتركيز أيضًا أثناء touch mode كي ينجح التركيز المطلوب عند بدء النافذة، واستُبدلت مقارنة النقطتين بقياس مجال التباين على شبكة تغطي الشاشة (>80) مع حفظ الصورة قبل الفحص. بقي اختبار أسهم D-pad وOK وBack وحفظ الهوية والإعدادات كما هو؛ لا حذف لتوقعات التنقل. الفحص الكامل يُعاد بعد هذين الإصلاحين، ويجب قراءة نتيجته الفعلية قبل التسليم.

أظهرت المحاولتان التاليتان مشكلة fixture أخرى: ShadowActivity.getCurrentFocus في Robolectric4.13 حقل mock منفصل يعيد null رغم تركيز View فعليًا؛ فُحص bytecode المحلي وأصبح الفحص يقرأ decor.findFocus. ثم ثبت أن Activity.dispatchKeyEvent وحده لا يمر بمرحلة تنقل التركيز في ViewRootImpl؛ نُقلت أحداث D-pad المؤلفة إلى dispatchInputEvent في جذر النافذة المرفقة، وأُبقيت توقعات الأسهم وOK وBack كما هي. نجحت الحالات الـ54 كاملة بعد ذلك، بلا تجاوز أو retry داخل الاختبار؛ سجل الريموت: key21 → الاتصال، key23 → الاتصال، key4 → الإجراء الرئيسي. حُفظت سجلات الأعطال الوسيطة منفصلة. جرت مراجعة الصور وكُبّر النص والأزرار لتناسب المشاهدة من بعيد. كود التطبيق النهائي تَجَمّع ومرّت عليه الفحوص؛ لم تُستخدم نتيجة تشغيل فاشل كتسليم.

## التثبيت والقبول الفعلي

لا جهاز متصل في `adb devices`. فشل اتصال TCP واحد محدود بثلاث ثوانٍ بعنوان TV المحفوظ على منفذ5555؛ لم يُجرَ مسح للشبكة أو محاولة اقتران جديدة. سُئل المستخدم عن تشغيل TV على الشبكة نفسها أو عنوانه الحالي أثناء استمرار العمل المستقل. لا تدّعِ التثبيت أو الاختبار على TCL بمجرد تجهيز APK.

عند توفر الوصول: تحقّق من الهوية TCL / Smart TV Pro / G10 / Android12 / Aljulanda TV والحزمة والتوقيع والإصدار الموجودين قبل التثبيت. تحديث `pm install -r` فقط بنفس الهوية؛ لا حذف بيانات أو تطبيق أو تغيير Home/إمكانية الوصول أو منح إذن overlay جديد. لا تنزيل أو معالجة أو اختبار خاص جديد بـRDR2. احفظ دليل الإصدار المثبت بعد التحديث. يلزم اختبار الريموت والإذن والاقتران الموجود/QR والمصدر القديم والحوار والقائمة واختفائها/تغيرها وقطع الاتصال واستعادته على الجهاز الفعلي.

الرجوع: revert لالتزام دفعة TV وإعادة البناء برقم تحديث مناسب؛ لا تمسح التطبيق للمحاولة. حافظ على المفتاح الأصلي وبيانات الاقتران. بقي المصدر/ملفات الإصدار السابق محفوظة، ولا نشر release عامة تلقائيًا.
