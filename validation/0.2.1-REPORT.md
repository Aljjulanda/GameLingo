## Findings and implementation

### Punctuation and actual RTL layout

The old speaker prefix isolated `name:` together. The TCL StaticLayout fixture reproduced the colon on the far side of the English name. The replacement isolates the English name with LRI/PDI and puts RLM, colon and non-breaking space outside it, inside the existing RTL paragraph. Six names were verified with actual glyph selection bounds, paragraph direction, first-line membership, color spans and wrapping: Arthur, John, Master Chief, Lara Croft, O'Brien and Dr. Smith. BidiFormatter was rendered as an alternative; no additional dependency was needed.

Source tracing found no presentation code that intentionally adds parentheses around translated dialogue. The origin of the user's particular brackets remains **unconfirmed** without a raw example; they can come from game text, OCR, translation, or visual ordering. No universal bracket deletion or string reversal was introduced. The new presentation layer removes incoming directional format controls, preserves meaningful parentheses, square brackets, quotation marks, punctuation and newlines, and isolates Latin/numeric terms inside Arabic. Signed numbers, Unicode minus and Latin accents have regressions. The final TV fixture contains balanced Arabic parentheses, square brackets, quoted English, numbers and multiline text.

The iPhone exposes content-free punctuation counts at OCR, parsed English, raw model output and wire output. Wire tests preserve the actual punctuation. Android state stores logical text; SpeakerText creates color spans and controlled isolates; the existing StaticLayout/Canvas renders it. Counts do not identify whether an individual recognized bracket was in the game or invented by OCR. They provide stage evidence without exporting dialogue.

### Structured speaker detection

The existing Vision pass now retains observations, boxes, confidence and order until speaker classification. The classifier supports explicit inline colon labels, names above dialogue, smaller nearby labels, labels at either side and up to three dialogue lines. Vision can merge a side label with dialogue into one observation: the implementation uses recognized per-range character boxes and a measured gap to split a plausible name from the body. Body geometry excludes the label, preventing a missing label from moving the event anchor.

Names allow up to three words, apostrophes, periods and hyphens. The manually configured dictionary remains optional and useful at lower confidence; the HUD/ordinary-word blocklist still wins, including WARNING, MISSION, OBJECTIVE, PRESS, HOLD, INVENTORY, OPTIONS, PLEASE, WAIT and RELOAD. Weak/unrelated evidence falls back to the existing conservative subtitle selection, rather than inventing a person. Speaker identity survives a missing label only within a matching event; an explicit different speaker creates a boundary. Case/period cosmetics do not create a different person. Labels must be visible inside the configured ROI; this is not full-screen semantic game understanding.

The original Vision ROI coordinate projection was verified against generated image coordinates and retained. No extra OCR pass or sampling-frequency increase was introduced.

### Event identity and duplicate suppression

Actual code in SubtitleEdit, VideOCR and subtitle-extract was read before implementation. Relevant revisions, paths, licenses and decisions are recorded in [the research record](0.2.1-RESEARCH.md). No code was copied and no OCR/video dependency was imported. Adopted ideas are short temporal continuity, confidence-selected wording, bounded comparison and observed blank boundaries; batch timing refinement and a universal fuzzy threshold were rejected for this real-time pipeline.

The iPhone keeps an event ID through exact/punctuation/wrapping changes, short OCR dropout, missing words and cosmetic variants. Lower-quality observations cannot progressively degrade the reference. A callback gap alone is not evidence that source dialogue disappeared: a new disappearance boundary needs at least two empty observations spanning 750 ms. An identical sentence can appear again after that confirmed boundary, an intervening line, different explicit speaker or spatial boundary. This deliberately favors continuity during an unobserved gap; an identical new utterance with no observed boundary cannot be proven.

Negation, numbers/signs, pronouns, directions, action words, proper names, destinations and here/there contrast receive conservative guards. High-confidence changed instructions are new events. A narrowly bounded initial low-confidence-to-high-confidence acquisition repair can update the same event. Cosmetic changes retain the displayed Arabic and clock; meaningful corrections remain possible. Similarity input is bounded to 512 characters. Translation reuse has eight entries; TV source fingerprints have sixteen; the TV's existing bounded display/expiry/tombstone policy is retained.

Interrupted events retain identity while pending/in-flight publications are invalidated. A late label cannot replay old dialogue after reconnect or Smart Reading. The TV uses optional protocol-v1 event-boundary/gap metadata as a second safety net for erroneous fresh IDs, limited to the latest continuous equivalent source. Legacy Windows messages without this metadata retain their behavior. Fresh IDs with a confirmed gap or speaker/spatial boundary, and repetitions after intervening dialogue, remain protected. Identical Arabic cannot compact away semantically changed source instructions.

### Recovery accounting and ownership

The previous `totalPS5Reconnects` callback counted admitted replacement attempts, not confirmed successful reconnections. The value 23 cannot establish successful connections or explain a nonexistent interruption in the corrected 30-minute trial.

Code inspection found a possible ownership race: lifecycle/network recovery could start a replacement while the native service already had a retry timer pending. A serial accounting gate now preserves the pending retry, connecting and login states. Session epochs and a live-session check reject stale/duplicate native callbacks. Manual Stop invalidates pending retries. Existing native Chiaki, decoder implementation, retry/backoff schedule and **12-second** starvation threshold remain unchanged. This repairs the verified ownership gap; it does not prove that it caused any historical device event.

Counters now distinguish actual admitted replacement attempts, native-connected confirmations, failed replacement starts/quits, admitted starvation replacements, decoder IDR requests, audio interruption transitions, NWPath availability losses, duplicate observations suppressed, corrections merged and accepted/uncertain formatted speaker readings. Speaker counters count readings, not unique people or ground-truth accuracy. Network counters represent NWPath availability loss, not every radio/transport issue. Reconnect success means native connected, not first decoded frame. Displayed successful-attempt duration excludes time waiting before that attempt; uptime and encoded/decoded frame ages are separate.

An 80-line sanitized session log records fixed stages, numeric native reasons, foreground/network/audio state and main-callback gaps. A callback gap is explicitly **not** labeled confirmed OS suspension. No registration key, token, PIN, certificate material or dialogue is recorded by these additions. The existing system sampling timer supplies telemetry; no aggressive network polling was added. Counter state survives automatic pause/resume and resets on a new user-started session.

## Validation and performance

Final build/test and measurement results are in `BUILD-VALIDATION.json` in the release. The compiled application source is `eccdbfe4e476e4a541a762ec615827d99e50a809`; the release source archive includes subsequent validation-only documentation. The final GitHub Actions run [43576726133](https://github.com/Aljjulanda/GameLingo/actions/runs/43576726133) **succeeded**, with 59 portable Swift tests, 15 Apple integration tests, four packaging-tool tests and a validated unsigned arm64 IPA. The final Android production build and 29 JVM tests passed, with zero failures.

- Existing baseline: 51 Windows tests and 24 Android JVM tests rerun successfully before application edits. Accepted 0.2.0 CI had 42 portable Swift, 14 Apple integration and four build-tool tests.
- New regression coverage: structured layout/confidence/name cases; 20-frame continuity; missing words/wrapping; observed blanks versus unobserved callback gaps; punctuation/wire fidelity; numeric sign and semantic instruction changes; late speaker metadata; real repetition; retry ownership/counters/login/Stop; bounded logs; Android expiry/tombstones/aliases/visible counts.
- Apple tests use generated text/pixel buffers, actual Vision, native offline inference, VideoToolbox without continuous rendering, audio interruption/Stop policy, Keychain/TLS and Android-compatible OkHttp over the simulator's LAN. These are **simulator/CI** results, not an actual iPhone-to-TCL gameplay run.
- Final actual TCL Android 12/API 31 tests: RTL glyph/color/wrapping/punctuation fixture passed; existing Canvas clock/anchor/document regression passed; real Receiver/OkHttp with unchanged Windows LAN server passed TLS pinning, encrypted token storage, saved-token reconnect, source/revision replacement, settings ACK, ping/pong, document pages/close and obsolete-host mDNS recovery while preserving full pin/token.
- `TCL-RTL-0.2.1.png` is an original Canvas image rendered on the TCL and inspected visually. The opaque test board was attached to a Lab overlay. TCL HDMI compositor `screencap` returned zero bytes; this artifact is **not a physical-screen screenshot**. Six-name assertions inspect glyph bounds, not string equality alone.
- Actual TCL cached presentation path: 1,000 repeated inline calls took **13.934408 ms** in the final fixture. This excludes StaticLayout, OCR, model inference and gameplay and is not a device-wide CPU benchmark.
- A repeatable optimized portable-Swift benchmark compiles actual stable-tag and development tracker code on the **same CI Mac**, three runs of 10,000 observations. Emitted jobs decreased from 751 to 501 (33.29%). Median tracker time increased from 3,690.55 ms to 7,837.79 ms per 10,000 observations: 0.369 to 0.784 ms per observation, an additional 0.415 ms. The new checks cost about 2.12 times as much in this isolated tracker microbenchmark; reduced job churn does not prove lower total phone CPU. Release JSON contains every sample. Job count is not an exact count of displayed cards or translations. No comparative iPhone CPU, RSS, p95, thermal or energy measurement was obtained.

No continuous video renderer, new model, new OCR request, larger context archive or persistent subtitle history was added. Native C, VideoDecoder, FrameSignature, OfflineTranslator, BackgroundAudio, TLS/authentication and the Windows program remain unchanged. This limits scope but does not establish unchanged phone power consumption; physical measurement is still required.

Lab used `dev.gamelingo.tv.lab` with independent preferences/Keystore. Both Lab packages were removed after tests. Production `dev.gamelingo.tv` remained 0.6.0 (8), foreground overlay service running, overlay permission allowed. The delivered production APK is 0.6.1 (9) with the original signer SHA-256 `48cf8a45a37f4e5c338f98fa7d5135c7cdbaf59d50b39b8bf591a79622a28e38`.
