## User evidence and control fix

The owner supplied a screenshot of an empty rightmost Control Center tile.
It establishes missing rendered content, not the installed build/signing state.
Build 12's value provider throws when the signed App Group container is missing;
this prevents the control's configuration content from loading. That is a
code-supported possible cause, not a verified device diagnosis.

- Provider now returns unknown status for an unavailable container or expired
  state; it never intentionally fails rendering on that path.
- The primary `ControlWidgetButton` label always contains `gamecontroller.fill`.
  The display name and kind remain GameLingo / the existing control identifier.
- Each press runs `ToggleTranslationIntent` in the app process. The actual app
  decides start/stop from its running or pending-load state. Missing, stale, or
  incorrectly signed shared defaults cannot force every press to mean start.
- Fresh shared state still supplies a start/stop label. Unknown status shows
  GameLingo without inventing an on/off state. As a button the tile has no
  system toggle highlight. The existing explicit SetValueIntent is retained.
- Automatic foreground opening remains disabled. OS execution restrictions,
  force-quit delivery, and actual system routing still require a signed iPhone.

## Status notifications

- `SessionFeedbackState` observes actual session phases. Starting/recovering
  never says success; the connected `.active` phase produces the success notice.
  Failure during prerequisites/model load/connection is explicit. Stop and finite
  background suspension have separate notices. Repeated phase samples are quiet.
- In the active app, a dismissible SwiftUI material banner shows Arabic status,
  an icon, adaptive text, a subtle border/shadow, and a brief transition. It
  respects Reduce Transparency, Reduce Motion, Dynamic Type, RTL, and VoiceOver.
- Outside the app, allowed local iOS notifications show status only, without
  sound/badge/gameplay text/screenshots. iOS owns the external banner's appearance;
  the app cannot guarantee a custom glass presentation over other applications.
- One notification identifier replaces old status. Serialized delivery plus
  generation checks prevent a delayed start notice from replacing a newer stop.
- Ask for alert authorization once, in context on an in-app Start press or via
  Settings > Translation and language > Translation status notifications. Never
  ask from a background control action or automatically open the app for consent.
  Denial does not block translation or in-app banners; settings link permits
  changing the system choice. Focus/banner preferences still govern delivery.
