# تحديث GameLingo — Windows 0.3.1 وTV 0.3.0

## المنفذ

- أُصلح المسح المبكر الناتج عن اختفاء نص OCR أو وصول جملة جديدة.
- التلفزيون يدير 1–3 جمل بمؤقتات مستقلة تبدأ عند الرسم. الرابعة تُظهر فورًا وتحذف الأقدم. الجملة الجديدة ثابتة عند مرساتها، والجمل السابقة تمتد لأعلى.
- مدد القراءة الافتراضية 4–8 ثوانٍ، بسرعة 13 حرفًا غير فارغ في الثانية، مع وضع مدة ثابتة وإعدادات للارتفاع والعدد والتباعد.
- صفحة «إعدادات عرض الترجمة» تتضمن 40 قيمة للخط، الوزن، الألوان، العتامة، الحدود، الظل، الخلفية، الالتفاف، المحاذاة، القراءة والموضع. التحكم بالموضع يدعم 1/5/10/50 بكسل وخطوة مخصصة مع إدخال X وY.
- معاينة محلية ومعاينة على TCL، أنماط Classic وCinema وGaming وMinimal، وحفظ أنماط خاصة. المعاينة المحلية تقريبية لاختلاف خطوط النظام؛ معاينة التلفزيون هي المرجع.
- Windows يحفظ الإعدادات ويعيد إرسالها عند الاتصال. التلفزيون يحفظ أحدث إعدادات مقبولة ويرفض الأقدم.
- صفحة «الأداء واستهلاك الموارد» تقيس CPU وRAM للنظام وGameLingo وعمليات chiaki، مع أزمنة مراحل المعالجة والذاكرة المخبأة وطابور العمل ورسم CPU خفيف كل ثانية.
- أوضاع Economy وBalanced وPerformance بحدود ابتدائية 2/4/8 OCR في الثانية. الحد قابل للتعديل. الإدارة الآلية تستخدم حملًا مستمرًا وفترة تهدئة، ويمكن تعطيلها.
- أُزيلت أوضاع القوائم وكامل الشاشة من الواجهة الجديدة. قراءة الحوار والمنطقة المخصصة وملفات الألعاب قائمة. لا توجد واجهة سجل حوار أو إعادة عرض.

## الاختبارات

- Windows: 22 اختبارًا ناجحًا.
- Kotlin: 7 اختبارات ناجحة تشمل عشر جمل بفاصل ثانية، المؤقتات المستقلة، التكرار والتصحيح، حدود السعة، الحسابات التكيفية والثابتة، ثبات المرساة والتحريك ببكسل واحد.
- TCL الحقيقي: وصل إعداد 1920×1080، وسجّل عشر جمل متتالية بسعة قصوى ثلاث، مع طرد الأقدم. تغيرت المرساة X=960 إلى X=961 وعادت إلى X=960.
- أكد المستخدم أن المعاينة واضحة وأن التكديس صحيح.
- عينة نافذة الحوار ذات الست جمل السريعة: 6/6 قبل التعديل وبعده.
- اختبار ذاكرة ثابت لمدة 120 ثانية اكتمل بلا أخطاء. RAM بعد الإحماء 186.9 MB وفي النهاية 187.0 MB. لا يمثل ذلك اختبار تشغيل متعدد الساعات.

## قياسات المقارنة

نُفذت عينة النافذة نفسها على الكمبيوتر ذاته. CPU أدناه نسبة من كامل المعالج، والذاكرة RSS للبرنامج، والزمن من تحديث نص نافذة الاختبار حتى جاهزية ترجمته، ويشمل انتظار العينة. يتضمن الاختبار بدء عملية وتحميل نموذج.

| القياس | قبل | بعد |
|---|---:|---:|
| متوسط CPU للبرنامج | 15.9% | 16.1% |
| ذروة RAM | 248.6 MB | 247.4 MB |
| وسيط الزمن | 265.5 ms | 297.5 ms |
| المئين 95 | 391 ms | 344 ms |
| الجمل الفائتة | 0/6 | 0/6 |

لا تُظهر هذه العينة القصيرة انخفاضًا عامًا في CPU. في عينة مخصصة لخلفية تتحرك مع ثبات النص، كان عدد اختلافات الإطار 60 خلال ست ثوانٍ، وطلب المجدول الذكي OCR عشر مرات مع التحقق الدوري. هذه أعداد للعينة، وليست نسبة تحسن مضمونة لكل الألعاب.

GPU غير متاح بقياس موثوق في اللوحة الحالية. بقيت معالجة الترجمة على CPU بنموذج int8 الموجود، ولم تُفعّل مكتبات GPU إضافية. تجارب مقارنة فك الفيديو عتاديًا ومجموعة ألعاب موسعة وتشغيل متعدد الساعات ما زالت غير منجزة لهذا التحديث.

## ملفات التعديل الرئيسية

Desktop: pipeline.py، network.py، ui.py، appearance.py، display_settings.py، performance.py وملفات الاختبار والقياس.
Android: OverlayService.kt، Receiver.kt، SubtitleCanvas.kt، SubtitleState.kt، LayoutPolicy.kt واختباراتها.

بقيت مفاتيح التوقيع والاقتران والنماذج وإعداد UrTV محفوظة. خط الأساس القابل للاسترجاع هو Git tag baseline-before-smart-subtitles داخل أرشيف المصدر.

## الاستخدام

1. من «إعدادات عرض الترجمة» اختر النمط وعدّل ما تريد. التغييرات تُرسل بعد توقف قصير عن التعديل، وزر «تطبيق وحفظ» يثبتها فورًا.
2. X وY إزاحتان عن مرساة أسفل الوسط، بالبكسلات الفيزيائية للتلفزيون. ↑ يقلل Y و← يقلل X. الحواف تُقيّد الموضع حتى يبقى النص في الشاشة.
3. من «الأداء واستهلاك الموارد» اختر Balanced كبداية. Performance يرفع سقف القراءة للحوار السريع، وEconomy يخفضه.
4. حساب البث في chiaki مستقل عن حساب اللعب. استخدم الثاني للبث عند اللعب بالأول، كما ثبت في الاختبار السابق.


## حدود تحت الحمل المرتفع

في تشغيل موازٍ لضغط حزمة التثبيت وإرسال اختبار التلفزيون، لم تلحق نافذة الحوار بخمس من ست جمل سريعة. عند إعادة اختبار الملف التنفيذي منفردًا نجحت الجمل الست، دون فقد. لا توفر هذه الاختبارات ضمانًا للحوار السريع أثناء تشبع المعالج ببرامج أخرى. تقارير المحاولة المجهدة وإعادة الاختبار محفوظة في evidence. يُنصح بإتمام البناء والتثبيت قبل جلسة اللعب.

حزمة APK محدّثة ومثبتة على Aljulanda TV بنفس هوية التوقيع السابقة، وبناء Windows مثبت مع اختباراته. لم يُجر اختبار GPU أو مقارنة ترميز الفيديو في جلسة لعب جديدة لهذا التحديث. اختبار الذاكرة المرفق مدته دقيقتان فقط.

أُغلقت نافذة chiaki الخاملة الزائدة التي كانت تستهلك قرابة 624 MB؛ بقي ملف البث الثاني مسجلًا. القياسات في الجدول تخص عملية GameLingo وعينة الحوار، ولا تحسب إغلاق النافذة كتخفيض داخل محرك OCR.

رُقّي رقم مثبت Windows إلى 0.3.1 بعد أن رفض Windows Installer إصلاح حزمة محلية معدلة بنفس رقم 0.3.0. استخدمت الترقية هوية المنتج المستمرة وطابقت بصمة الملف التنفيذي بناءه النهائي.

التحقق النهائي: اجتاز الملف التنفيذي المثبت اختبار الاستدلال وTLS واختبار نافذة الحوار بست جمل دون فقد. بعد آخر تحديث APK أُعيد الاتصال تلقائيًا بهوية الاقتران المحفوظة، حتى أثناء سكون الشاشة. بقيت sa.urtv.home/sa.urtv.home.NetflixShortcutService مفعّلة، وشاشة sa.urtv.screensaver/.ScreenDream مضبوطة. إعدادات المظهر محفوظة في Windows وتُزامن مع TV.
