# Dialogue Focus update — Windows package 0.4.1 / TV 0.4.0

The existing WGC → Windows OCR → Argos CPU int8 → private TLS/WebSocket → native Android Canvas pipeline remains intact.

Default Windows sessions enable a game-profile normalized dialogue ROI with a native-frame visual editor. `capture.native_roi` uses the same rounded pixel boundaries as the crop. `DialogueFilter` combines spatial geometry, menu/prompt terms, row density, and observed persistence; Windows OCR supplies rectangles but no confidence. Strict mode requests a prompt second sample. Short centered dialogue is accepted in Balanced mode. These heuristics cannot semantically distinguish all menus from dialogue in identical positions.

Only newly recognized, fresh frames affect `Tracker`/`Presence`. Two valid blank observations produce a `subtitle_source_gone` event; skipped OCR and repeated stale frame timestamps do not. Adaptive small-edge signatures see bright/dark captions, retain verification, and avoid the prior full-region byte hash when active. One translator/model instance, bounded pending dialogue, stale-result cancellation, optional low-priority context work, 256 RAM entries and 2048 SQLite entries remain bounded. Context is disabled by default and adds no OCR while disabled.

Protocol v1 is retained. New messages are `subtitle_source_gone`, `context_show`, `context_present`, `context_clear`. Connection setup clears active TV state and syncs appearance; it never replays an old subtitle. Settings include `fit_background`, `disappearance_grace`, `hard_seconds`, `fade_ms`, and the context styling keys. Android owns the reading clock and never renews dialogue deadlines for duplicates/corrections. Hard lifetimes are finite with no automatic extension. Source-gone shortens a deadline to at least the minimum reading time plus the grace policy. Pending entries too old before first render are discarded; a bounded seen-ID set prevents late duplicates resurrecting expired entries within the session.

The Canvas drains at actual drawing, rearms its Handler after draining, and includes pending entries in scheduling. This fixes the empty-list-before-first-draw race. Deadline checks also occur at draw. A measured child layout gives each sentence its own content-sized box, constrained by the configured maximum width. Anchor safe bounds reserve the configured maximum width so varying text widths never move an anchor near screen edges. Fade occurs locally; only actual session stop/disconnect clears all entries.

Context requires an explicit single ROI, calibrated video rectangle, source aspect consistency, TV dimensions, and confirmation of complete uncropped 16:9 HDMI. It projects crop-native OCR rectangles through video normalization into TV physical coordinates. Mismatched calibration disables positioning. A single context label sits below the source, or above when the lower area would conflict, is clamped to screen bounds, uses separate smaller styling, expires in 1.8 seconds without valid presence, and never owns touch/focus. Disabling it is immediate; enabling requires restarting a validated session. Dense menu translation is excluded.

`gpu_metrics.GPU` opens one native Windows PDH query; its bounded transient engine array is read every two seconds in the dashboard. Usage aggregates process contributions per physical engine and reports the busiest engine. Unsupported counters disable the GPU readout cleanly. The monitor does not launch polling subprocesses. Native samples measured 1.5–3.5ms on this host. CPU monitoring remains one second and history is a bounded 90-point resource graph, not dialogue history.

`--start-translation` launches the existing saved Chiaki source/listener and starts once paired TV reconnects, without a test timeout. Normal GUI launch remains ready for manual Start. Model data/pairing remain in the existing local data directory. The v0.4.1 MSI is a normal per-user major upgrade with the existing UpgradeCode. The APK uses the existing application ID and signing identity. No UrTV package/settings, signing secrets or PS5 HDMI configuration are changed.

Run `pytest desktop/tests`, `scripts/android-build.sh` (existing JDK/SDK/Gradle), `scripts/tcl-canvas-test.sh` through Git Bash with explicit verified `TV_HOST` and `URTV_DIR`, and the repeatable benchmark scripts. Physical assertions use generated Arabic content only. Full results, mixed resource findings, current device limits and all benchmark rounds are in `DIALOGUE_FOCUS_RESULTS_AR.md` and `evidence/dialogue-*`.
